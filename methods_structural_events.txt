\section{Inference of junction evolution and structural genomic changes}
To structurally analyze accessory genome junctions, we developed a computational framework to cluster similar accessory paths in a junction, infer ancestral block structures, and detect structural genome events (Figure~\ref{fig:workflow}a-d).
\begin{figure}[bt]
    \centering
    \includegraphics[width=1\textwidth]{figures/workflow.pdf}
    \caption[Computational framework for junction clustering, ancestral block reconstruction, and detection of structural events.]{
    \textbf{Computational framework for junction clustering, ancestral block reconstruction, and detection of structural events.}
    (a) Junctions are clustered based on sequence similarity of their flanking core genome blocks. For each junction, a local phylogeny is inferred from the combined alignment of its core blocks. Branches exceeding $0.001$ substitutions per site are cut, and clusters correspond to the remaining connected clades.
    (b) For each cluster, the ancestral block structure is reconstructed. Duplicated blocks are resolved by selecting an anchor block to the left, and remaining ambiguities are handled by assigning numerical labels to ensure unique block–context combinations. The presence or absence of deduplicated blocks in the most recent common ancestor is then inferred along the global core genome phylogeny using the Fitch algorithm. If the root state is ambiguous, gain and loss events are distinguished using block sequence similarity. Single blocks are interpreted as single insertion events.
    (c) Consensus paths are used as references to detect structural events such as insertions, deletions, translocations, and inversions. Detected events are grouped by independent acquisition clade and merged into multi-block events.
    (d) The final output summarizes the evolutionary history of each junction, separating homologous recombination from secondary structural variation. The complete history can be explored in an interactive dashboard.
    \label{fig:workflow}}
\end{figure}

\subsection{Grouping junctions by underlying homologous recombination events}
Homologous recombination can introduce large structural changes in the accessory genome, resulting in a block structure that appears clustered by overall architecture and can obscure the detection of subsequent, smaller-scale events. Therefore, junctions must first be grouped according to the homologous recombination events that might have contributed to their diversity before meaningful statements about finer structural variation can be made.
To achieve this, we exploit the observation that homologous recombination events are typically associated with increased sequence divergence in the flanking core blocks \cite{oliveira_chromosomal_2017}, a pattern that is also evident in our data. We therefore cluster junctions based on sequence similarity in these flanking core regions.
First, the combined core blocks from all isolates are aligned using \texttt{MAFFT v7.526} \cite{katoh_mafft_2002, katoh_mafft_2013} with default parameters and automatic algorithm selection. Phylogenetic trees are then reconstructed from the resulting alignment using maximum-likelihood inference implemented in \texttt{FastTree 2.2.0} \cite{price_fasttree_2010}, under the General Time Reversible (GTR) substitution model for nucleotide sequences, with gaps treated as missing data.
Clustering is performed by cutting the resulting trees at branches exceeding $0.001$ substitutions per site (Figure~\ref{fig:workflow}a), a threshold substantially higher than expected under vertical descent ($<10^{-4}$), as observed in the phylogeny based on the recombination-filtered core genome alignment.

\subsection{Phylogeny-based reconstruction of consensus paths}
To reconstruct consensus paths representing the most likely block structure of the most recent common ancestor (MRCA) within each cluster, we leverage isolate relationships inferred from the core genome tree, which reliably approximates the clonal phylogeny of closely related isolates \cite{arnold_horizontal_2022}.

We first resolve duplicated blocks. For each duplicated block, context anchors are defined as the nearest blocks to the left that (i) occur in more than $20\%$ of isolates in the cluster, (ii) are not duplicated, and (iii) are not inverted. To prevent long duplications or inversions from interfering with anchor identification, isolates are excluded if fewer than $60\%$ of their blocks can serve as anchors, provided that at least $80\%$ of isolates remain after filtering. When this condition is not met, the filtering threshold is relaxed such that only isolates with fewer than $30\%$ of anchor blocks are removed, or no isolates are excluded. If block–anchor combinations remain non-unique due to repeated blocks in close proximity, the context is further distinguished by appending an index reflecting the order of the blocks along the genome.

After deduplication, each remaining isolate is binary encoded to indicate the presence or absence of every block ID–context combination. Blocks occurring in the same context but with opposite strandedness are treated as identical to avoid inversions artificially enforcing absence in the consensus. Block presence or absence is inferred using the Fitch algorithm \cite{fitch1971toward} applied to the binary-encoded sequences along the core genome tree, subsampled to the remaining isolates of the cluster. When the root state is uniquely determined, it defines the consensus state. Remaining ambiguities are resolved using sequence similarity between different block occurrences within the cluster. Blocks with low sequence similarity (average pairwise divergence per site $>0.001$) are interpreted as independent insertion events and are therefore considered absent in the MRCA, whereas highly similar blocks are assumed to have been present in the MRCA and subsequently lost in some lineages. To calculate the average pairwise divergence within a block, all block occurrences within a cluster are aligned using \texttt{MAFFT v7.526} \cite{katoh_mafft_2002, katoh_mafft_2013}, applying the same parameters used for the core genome block alignments. If a block occurs only once, sequence similarity cannot be evaluated, and a single insertion event is assumed, implying absence in the MRCA (Figure~\ref{fig:workflow}b).

Finally, the consensus path is reconstructed by removing all non-consensus blocks from the isolates and deriving a majority path from the filtered block arrangements. After consensus construction, both consensus paths and isolates are re-deduplicated while considering all isolates to ensure consistent and unique block ID–context combinations. Because all clusters are included at this stage, blocks require only a minimum frequency of $10\%$ to qualify as anchors.

\subsection{Detecting structural events relative to the consensus path}
Structural events are detected by comparing each isolate to the reconstructed consensus path (Figure~\ref{fig:workflow}c). We distinguish four event types: insertions, deletions, inversions, and translocations.

The context definition used for consensus reconstruction excludes blocks that are duplicated or inverted in any isolate. In the presence of large duplications or inversions, this can lead to extended regions without context anchors, making the definition unsuitable for detecting smaller structural events. Therefore, instead of relying on a global context definition, each isolate is compared individually to the consensus path, and context anchors are defined separately for each isolate.

For a given isolate, context anchors are blocks that occur exactly once in both the consensus and the isolate path and share the same strandedness. We then perform a preliminary detection step to identify translocations, since such blocks should not serve as anchors. The isolate is iteratively scanned for translocated block IDs, which are removed from the set of potential anchors, and the context definition is updated accordingly. This procedure is repeated until no additional translocated blocks are detected.

Using the resulting final context definition, structural events are classified as follows:
\begin{itemize}
    \item \textbf{Translocations} are blocks that share the same block ID but occur in a different context compared to the consensus path.
    \item \textbf{Insertions} are blocks that do not occur in the consensus path with the same block ID and context and are not classified as translocations.
    \item \textbf{Deletions} are blocks present in the consensus that do not appear in the isolate with the same context and are not classified as translocations.
    \item \textbf{Inversions} are blocks that appear in the same context as in the consensus but with opposite strandedness.
\end{itemize}

\subsection{Phylogeny-based grouping and merging of structural events}
To determine whether the same structural event occurred independently in different lineages or was inherited from a common ancestor, per-block events are grouped phylogenetically before adjacent blocks are merged into longer events.

For each unique combination of event type, block ID, strandedness, and context, the set of isolates carrying that event is mapped onto the cluster subtree and independent acquisition events are identified using binary Fitch parsimony \cite{fitch1971toward}. Including strandedness in the grouping key ensures that blocks with the same ID and context but opposite orientation are not conflated into a single acquisition history. Each $0 \to 1$ gain edge in the top-down resolved tree defines one independent acquisition; the isolates below that edge that actually carry the event form one clade. To correctly handle gain–loss–regain patterns, in which a re-acquisition within a broader gain clade would otherwise cause its isolates to be attributed to the higher-level event, each gain edge is assigned only the isolates that lie exclusively below it and not below any nested gain edge. The most recent common ancestor (MRCA) of those isolates is recorded as the \textit{parent clade identifier} (\texttt{parent\_clade\_id}) of the event, and every corresponding event node in the isolate paths is annotated with this identifier.

Adjacent per-block events of the same type and \texttt{parent\_clade\_id} are then merged into longer events by walking each isolate path from left to right. The merging rules differ by event type:
\begin{itemize}
    \item \textbf{Deletions}: consecutive deletion nodes with the same \texttt{parent\_clade\_id} are merged. A deletion node whose \texttt{parent\_clade\_id} is an ancestor of the current group's clade is treated as a jump — it belongs to a broader co-occurring deletion and does not interrupt the current group. Any matched, inverted, or inserted node interrupts all open deletion groups.
    \item \textbf{Inversions}: consecutive inversion nodes with the same \texttt{parent\_clade\_id} are merged. Deletion and insertion nodes are jumped over without interrupting the inversion group. Any matched node interrupts all open inversion groups.
    \item \textbf{Insertions}: consecutive insertion nodes with the same \texttt{parent\_clade\_id} are merged. A descendant-clade insertion (whose \texttt{parent\_clade\_id} is closer to the tips than the current group) is treated as a jump — it belongs to a more recently acquired sub-event nested within the current insertion and does not interrupt it. An ancestor-clade insertion closes all currently open descendant groups and starts or continues a group at the higher level. Matched or inverted nodes interrupt all open insertion groups. Deletion nodes interrupt the tracking of contiguous insertion context but do not close open insertion groups.
\end{itemize}

To correctly associate lower-level insertions that are nested inside a larger higher-level insertion event, the context of such insertion blocks is re-assigned during merging. Specifically, if a lower-level (descendant-clade) insertion group begins within a contiguous stretch of insertion-only nodes that also contains a preceding higher-level (ancestor-clade) insertion — with no matched, deleted, or inverted nodes between that higher-level insertion and the start of the lower-level group — the context of every node in the lower-level group is replaced with the block ID of the last higher-level insertion node before it. This places the nested insertion relative to its enclosing higher-level event rather than the original consensus position, enabling correct downstream summarization.

After merging, events are deduplicated across isolates. Events sharing the same junction name, consensus path, merged block path, and \texttt{parent\_clade\_id} are treated as a single event, and the full list of isolates that carry it is recorded as an additional attribute.

Because the analysis is restricted to the local context of a single junction, we distinguish insertions from translocations only within that local framework. Consequently, events classified here as insertions may in some cases represent translocations or duplications originating from other genomic regions.
